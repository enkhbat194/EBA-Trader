## Closed issues

### Strict crossover / window-boundary bias

A bullish EMA state at a research/test boundary must not invent a BUY. Trend V1 now requires an actual False→True crossover; exits require True→False.

### Causal walk-forward warm-up

Test indicators may use prior train history as causal warm-up, but test performance, exposure and benchmark begin only at the unseen test boundary.

### Same-candle regime leakage

Trade-entry regime labels use only completed history before entry, not the candle opening at the same timestamp as the trade.

### Exact historical coverage

A dataset can no longer pass merely because it has no internal gaps. Exact first open, last open, expected candle count, interval spacing and close timestamps are required.

### Public-data retry behavior

Historical public market-data requests have bounded retry/backoff for rate limits, transient server failures and network errors.

### BTC benchmark risk

BTC buy-and-hold maximum drawdown is reported alongside return. Strategy risk advantage can therefore be measured rather than asserted.

### Development screening fixed before data

Minimum gates for validation, cost stress, parameter-neighborhood robustness, rolling walk-forward and BTC-relative return/drawdown tradeoff were declared before real development evidence.

### Freeze/verdict spoof protection

The freeze authority hashes evidence/verdict, recomputes screening from development evidence and checks the frozen OOS cache remains absent.

### Complete OOS configuration freeze

The authorized OOS path derives symbol, interval, EMA pair, normalized research capital, cost scenarios, data directory and OOS dates from the freeze snapshot. Public OOS CLI market/capital overrides are disabled.

### Source provenance

Development evidence records Git commit, branch, tracked-tree cleanliness and Python runtime. Evidence generation rejects a dirty tracked working tree.

## Frozen-holdout information boundary

The first-cycle holdout is the **BTCUSDT 2025 period**, not merely a filename called `out_of_sample` and not merely a 15-minute CSV.

Therefore:

- a development window with any alternate name must still be rejected if its dates overlap the frozen period;
- the generic historical downloader must reject BTCUSDT 2025 overlap before making a network request;
- the protection applies across generic BTCUSDT timeframes (1m/5m/15m/1h/etc.), because looking at the same future BTC period at another resolution still contaminates the holdout;
- only the authorized frozen-OOS path may open that period after development screening and candidate freeze.

A dedicated `holdout_guard` centralizes this rule so it is based on dates and asset, not naming conventions.
